 1. Что такое Dependency Injection?

Dependency Injection (DI) — это механизм внедрения зависимостей, при котором необходимые объекты передаются классу извне, а не создаются непосредственно внутри него. В ASP.NET Core зависимости обычно предоставляет встроенный DI-контейнер.

 2. Какую проблему создает использование `new ProductService()` непосредственно в контроллере?

Использование `new ProductService()` создает сильную связь контроллера с конкретным классом `ProductService`. Из-за этого сложнее заменить реализацию сервиса и проводить тестирование контроллера.

 3. Для чего нужен интерфейс `IProductService`?

`IProductService` задает набор методов, которые должен предоставлять сервис. Контроллер работает с интерфейсом, а не с конкретной реализацией `ProductService`. Это уменьшает связанность между компонентами приложения.

 4. Что такое Constructor Injection?

Constructor Injection — это способ внедрения зависимости через конструктор класса. Зависимость указывается в параметрах конструктора, после чего ASP.NET Core автоматически передает необходимый объект.

Например:

```csharp
public ProductsController(
    IProductService service,
    ILogger<ProductsController> logger)
{
    _service = service;
    _logger = logger;
}
```

 5. Зачем регистрировать сервис в `Program.cs`?

Регистрация необходима для того, чтобы DI-контейнер знал, какую реализацию нужно создать при запросе определенного интерфейса.

В нашей работе используется:

```csharp
builder.Services.AddScoped<IProductService, ProductService>();
```

Это означает: когда контроллеру понадобится `IProductService`, ASP.NET Core должен предоставить `ProductService`.

 6. Что делает `AddScoped`?

`AddScoped` регистрирует сервис с временем жизни Scoped. В ASP.NET Core обычно создается один экземпляр такого сервиса на один HTTP-запрос. После завершения запроса экземпляр перестает использоваться.

 7. Для чего используется `ILogger<T>`?

`ILogger<T>` используется для записи сообщений о работе приложения. С его помощью можно фиксировать различные события, предупреждения и ошибки.

В нашей работе используются:

csharp
_logger.LogInformation(...)


и

csharp
_logger.LogWarning(...)


 8. В чем разница между Information, Warning и Error?

`Information` используется для обычных информационных сообщений о работе приложения.

`Warning` используется для предупреждений о потенциально проблемных или необычных ситуациях.

`Error` используется для сообщений об ошибках, которые произошли во время выполнения приложения.

 9. Для чего используется `appsettings.json`?

`appsettings.json` используется для хранения конфигурации приложения. В нашей работе в нем задается минимальный уровень логирования.

Например:

```json
"Logging": {
  "LogLevel": {
    "Default": "Information"
  }
}
```

Изменяя уровень на `Warning`, можно скрыть сообщения уровней `Information` и ниже.

 10. Почему слабосвязанный код проще изменять и тестировать?

Слабосвязанный код зависит от абстракций, например интерфейсов, а не от конкретных классов. Поэтому реализацию зависимости можно заменить без изменения основного кода контроллера. Это также упрощает создание тестов, поскольку вместо реального сервиса можно использовать тестовую реализацию.
