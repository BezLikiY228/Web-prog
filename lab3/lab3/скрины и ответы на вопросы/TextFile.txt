 1. Что такое Dependency Injection?

Dependency Injection (DI) — это механизм, при котором необходимые объекту зависимости передаются ему извне, а не создаются внутри самого объекта. В ASP.NET Core DI используется для автоматического создания и передачи сервисов в контроллеры и другие классы.

 2. Какую проблему решает DI?

DI уменьшает зависимость классов друг от друга и упрощает замену, тестирование и сопровождение компонентов программы. Например, контроллер использует `IProductService`, не создавая объект `ProductService` самостоятельно.

 3. Что такое слабая связанность компонентов?

Слабая связанность означает, что компоненты программы как можно меньше зависят от конкретных реализаций друг друга. Благодаря этому один компонент можно заменить другим без необходимости изменять весь остальной код.

 4. Для чего используются интерфейсы при DI?

Интерфейсы позволяют определить набор методов, которые должен предоставлять сервис, не привязываясь к конкретной реализации. Например, `IProductService` определяет методы работы с товарами, а `ProductService` реализует их.

 5. Что такое Constructor Injection?

Constructor Injection — это способ внедрения зависимостей через конструктор класса. В нашем проекте `IProductService` и `ILogger<ProductsController>` передаются в конструктор `ProductsController`, после чего ASP.NET Core автоматически предоставляет необходимые объекты.

 6. Для чего сервис регистрируется в Program.cs?

Регистрация сервиса в `Program.cs` сообщает DI-контейнеру ASP.NET Core, какую реализацию нужно использовать для определённого интерфейса и какой жизненный цикл объекта применять.

Например:

`builder.Services.AddScoped<IProductService, ProductService>();`

означает, что при запросе `IProductService` будет использоваться `ProductService`.

 7. Чем отличаются Transient, Scoped и Singleton?

`Transient` — новый экземпляр сервиса создаётся каждый раз, когда он запрашивается. Такой вариант подходит для небольших независимых операций, где не требуется сохранять состояние объекта.

`Scoped` — один экземпляр сервиса создаётся в рамках одного HTTP-запроса и используется в течение этого запроса. Такой вариант часто применяется для сервисов веб-приложений.

`Singleton` — создаётся один экземпляр сервиса на всё время работы приложения. Он используется, когда один общий экземпляр должен использоваться всеми запросами, например для хранения общих настроек или кэширования.

 8. Для чего используется ILogger<T>?

`ILogger<T>` используется для записи сообщений о работе приложения. С его помощью можно записывать информационные сообщения, предупреждения и ошибки. В нашем проекте `ILogger<ProductsController>` используется для регистрации операций с товарами.

 9. Чем отличаются Information, Warning и Error?

`Information` используется для обычных информационных сообщений о работе приложения.

`Warning` используется для предупреждений о ситуациях, которые не обязательно являются ошибками, но требуют внимания.

`Error` используется для сообщений об ошибках и исключениях, которые возникли во время выполнения программы.

 10. Для чего используется appsettings.json при настройке логирования?

`appsettings.json` используется для хранения настроек приложения, в том числе настроек логирования. В нём можно указать минимальный уровень логов для приложения и отдельных компонентов.

Например:

`"Default": "Information"`

означает, что будут отображаться сообщения уровня `Information` и более серьёзные сообщения, такие как `Warning` и `Error`.

Если установить:

`"Default": "Warning"`

то обычные сообщения уровня `Information` перестанут отображаться, а предупреждения и ошибки продолжат отображаться.
